# Frontend QA Walkthrough

> Page-by-page click-through script for verifying the live application.

Backend on `:8000`, frontend on `:3000`, `.env.local` set with `NEXT_PUBLIC_API_BASE=http://localhost:8000`.

---

## 0. Prerequisites

```bash
# In one shell
cd backend && AI_PROVIDER=auto uvicorn app.main:app --port 8000

# In another shell
cd frontend && npm run dev
```

Open `http://localhost:3000`.

---

## 1. Landing page (`/`)

What to do: scroll the page.

What you should see:
- "AI-Powered Maritime Intelligence Platform" hero.
- Sign In button top-right.
- Module cards, Use Cases, Live Network metrics.

**Unique value:** marketing only — no backend interaction. *Static is correct here.*

What's still static: the "12,480+ Vessels Tracked" stats are landing-page eye-candy; not driven by the backend.

---

## 2. Login (`/login`)

What to do:
1. Click any demo account pill (e.g., "Capt. James Blackwood — Fleet Admiral").
2. The form auto-fills email, password is `demo`. Click **Access System**.

What you should see:
- Button shows "Authenticating…" briefly.
- Redirect to `/dashboard`.
- The TopBar shows the user's name and role.

What is correct: a real `POST /api/auth/login` call (visible in browser DevTools Network tab), returning `{access_token, refresh_token, user}`. The access token is stored in `localStorage["glimmora_token"]`; a `glimmora_session` cookie is set.

What is incorrect: if you see "Invalid credentials" — backend isn't running, or you used a wrong password.

---

## 3. Dashboard (`/dashboard`)

What you should see:
- "Executive Bridge" h1.
- KPI tiles, AGI feed ticker, fleet map, congestion chart, fleet status.

**Unique value:** situational awareness — KPIs + alerts in 5 seconds.

What is correct: the page renders without errors after login. The backend exposes `/api/dashboard/kpis`, `/api/dashboard/risk-snapshot`, `/api/dashboard/agi-feed` — but the current dashboard components still read from frontend mock data files. Wiring these to fetch from the backend is a low-friction follow-up; the contracts are already defined and tested.

What is still static: KPI cards, AGI feed ticker, risk snapshot. Backend returns the same shapes, swap-in is a one-line change per component.

## 4. Fleet (`/fleet`)

What to do:
- Click the status filter tabs (All, En Route, At Port, Delayed, Flagged, Anchored).
- Type "glimmora" in the search box.
- Click a vessel row to open the right detail panel.
- Click the column headers to sort.

What you should see:
- Table of 100 vessels.
- Search narrows results.
- Detail panel shows AGI Recommendation if you're admiral / fleet_ops / risk_intel / trade_intel.

**Unique value:** prioritize — find the vessel that needs attention.

Backend equivalent: `/api/fleet/vessels?status=&q=&sort=`. The frontend currently filters in-memory; the backend supports server-side too.

## 6. Risk & Sanctions (`/risk`)

What to do:
- Type a vessel name in the screening box (e.g., "MSC Glimmora") and click **Screen**.
- Try a high-profile sanctioned name (e.g., "Volga"); should match in the live OpenSanctions API.
- Click a suggested pill ("DPRK Stellar").
- Filter alerts by type and severity.
- Click an alert card to expand.

What you should see:
- Result banner (red MATCH / green CLEAR), with explanation generated by Vertex (or stub).
- Alert feed shows 15 records.
- "+ Create alert" button visible only for admiral/fleet_ops/risk_intel.

**Unique value:** validate — clear an entity, or surface the risk.

What is correct: the backend's `POST /api/risk/sanctions/screen` is wired to OpenSanctions. In sandboxed dev environments without outbound HTTPS, it will return `source: "offline"` and an empty hits list — that's a graceful degrade, not a bug.

## 7. Trade (`/trade`)

What to do:
- Click a document card → smart contract panel populates.
- Click "+ New document" (admiral / fleet_ops / trade_intel).
- Click "Approve Document" (admiral only).

What you should see:

- Approval flips status to "Verified" and is persisted (refreshing the page should keep the state — when the page is wired to the backend list endpoint).

**Unique value:** move-forward — push a document through approval.

Backend wiring: `/api/trade/documents/{id}/approve` records the approval in the DB and writes an `audit_log` row.

## 10. Voyage New (`/voyage/new`)

What to do:
1. Fill **Ship name** and **IMO number** (try `9876543` to see "matched" return from `/api/ships/lookup`).
2. Pick **Origin port** ("Algeciras") and **Destination port** ("Rotterdam") via the autocomplete.
3. Set **Planned departure** and **Planned arrival** (datetimes).
4. Tweak Sensitivity / Tracking / Alerts segments.
5. Click **Start Tracking Voyage**.

What you should see: a `POST /api/voyages` with the full payload, returning `{ id }`, and a redirect to `/voyage/{id}`.

**Unique value:** prepare — configure the monitoring before it matters.

## 11. Voyage Live (`/voyage/v_001`)

What to do: open the page after login.

What you should see:
- TopBar with breadcrumb and phase pill.
- Map with planned route + current position.
- AI Brief card with `whatIsHappening`, `whatChanged`, `whyETAMoved`, `recommendation` — all generated by Vertex (or stub).
- Status card with ETA, progress, risk score.
- Event timeline.
- Alerts card with **acknowledge** buttons.

What is correct: the page is server-rendered from `/api/voyages/v_001/*`. The browser's DevTools Network tab will NOT show those calls — they happen server-to-server (Next.js Server Components). To verify the data flow, hit the backend directly or check the Playwright `voyage_live.spec.ts`.

**Unique value:** decide — see what's happening, why, and what to do.

## What is still gap-list (vs. the backend MVP)

1. Dashboard KPI tiles still read from frontend mocks; backend KPIs available at `/api/dashboard/kpis`. Trivial wiring.
2. Risk page alert feed reads from frontend mocks; backend has `/api/risk/alerts`. Trivial wiring.
3. Trade list still reads from frontend mocks; backend has `/api/trade/documents`. Trivial wiring.
4. AGI list still reads from frontend mocks; backend has `/api/agi/decisions`. Trivial wiring.
5. Voyage list shows one hardcoded card; backend has `/api/voyages`. Trivial wiring.
6. SSE on `/voyage/{id}` is exposed but the frontend doesn't yet subscribe. The store has `applyStream` ready.
7. Voyage chat composer button isn't yet wired to `POST /api/voyages/{id}/chat`. Endpoint is verified.

These are all swap-ins of `import { vessels } from "@/app/data/vessels"` for `await fleetApi.list()`. Each is a few lines and does not require any UI change.

## How to test the real application flow

```bash
# Start backend + frontend, then:
cd e2e
npx playwright test --reporter=list
```

Expect 15/15 passing in ~30s.
